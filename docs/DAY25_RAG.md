# День 25. Мини-чат с RAG и памятью

## Что реализовано

День 25 использует уже существующий веб-чат. Историю продолжает хранить JSON,
краткосрочным контекстом управляют режимы `full`, `summary`, `sliding` и
`facts`. Отдельная **память задачи** конкретного диалога явно хранит цель,
уточнения, ограничения, термины, решения и открытые вопросы. Это не новый режим
контекста и не Task State Machine: автомат этапов можно полностью выключить.

Память задачи включается своей галочкой в правой панели. После каждого успешного
обмена `deepseek-v4-flash` отдельным JSON-вызовом обновляет полный снимок. Сервер
валидирует его и сохраняет отдельную ревизию и usage; ошибка обновления не
отменяет основной ответ. Выключение не удаляет накопленное состояние, но оно
перестаёт передаваться модели и обновляться.

При включённом RAG каждый новый вопрос проходит обычный конвейер Дней 22–24:

1. поиск кандидатов в локальном SQLite-индексе;
2. optional query rewrite;
3. similarity-фильтр;
4. локальный CrossEncoder-reranker;
5. final top-K;
6. ответ DeepSeek с найденным контекстом и, в проверяемом режиме, с обязательными
   источниками и дословными цитатами.

## Автоматическая маршрутизация

В строке чата переключатель `Маршрут` имеет два режима:

- `Авто` — production-like режим Дня 25;
- `Только база` — прежний строгий режим, в котором весь запрос обязан быть
  подтверждён локальными документами.

В `Авто` каждый пользовательский ход сначала выполняет локальный embedding-поиск
по индексу. Этот probe фиксируется в техническом снимке, даже если чанки затем не
нужны для ответа. Однозначные формулировки бесплатно классифицируются правилами.
Только для неоднозначного намерения `deepseek-v4-flash` делает короткий JSON-вызов
и выбирает один маршрут:

- `rag` — локальные документы, а при включённом `Проверяемый` также строгие
  цитаты и серверная валидация;
- `task` — Task State и история активной ветки без требования цитировать PDF;
- `tools` — только реальные доступные MCP-вызовы, без имитации API;
- `hybrid` — локальные чанки вместе с фактически полученными результатами MCP;
- `general` — обычные знания модели с явной отметкой, что локальная база не
  использовалась.

Глобальный выключатель MCP всегда имеет приоритет над маршрутизатором. Если
выбран `tools`/`hybrid`, но MCP запрещены или нужный сервер не подключён, модель
обязана сообщить об отсутствии внешних данных. Для нестрогих маршрутов сервер
добавляет блок `Источники маршрута`: Task State, локальные файлы, фактически
вызванные MCP либо отметку об общих знаниях модели. Этот служебный блок не
возвращается в следующий модельный контекст.

Рекомендуемые настройки длинного сценария:

1. включить `RAG`;
2. выбрать `Маршрут: Авто`;
3. включить `Проверяемый`;
4. выбрать `Combined` и `Всё вместе`;
5. оставить candidate top-K 20, final top-K 5 и порог 0,83;
6. включить `Память задачи`; Task State оставить выключенным, если сценарию не
   нужен жёсткий жизненный цикл;
7. MCP разрешить и запустить только если сценарию нужны внешние актуальные данные.

## Как учитывается разговор

Для режима `combined` используются два независимых поисковых канала:

- 70% — прямой поиск по последнему вопросу пользователя;
- 30% — поиск по самостоятельной contextual-формулировке.

Contextual rewrite получает только ограниченный снимок:

- до двух предыдущих сообщений пользователя;
- последний ответ ассистента без блоков «Источники» и «Цитаты»;
- активный summary или Sticky Facts выбранной стратегии;
- компактную включённую память задачи;
- описание, план, нестандартный текущий шаг и этап Task State, если они реально
  заполнены или изменены.

Текущее сообщение в этот снимок не дублируется. Полная история, технические
снимки старых запросов и тексты ранее найденных чанков в поиск не передаются.
Contextual rewrite выполняется до окончательного relevance-gate, поэтому короткое
уточнение вроде «а вторая?» не блокируется слабой прямой формулировкой. Для
контекстного канала применяется адаптивный порог на 0,03 ниже основного. После
двух поисков результаты удаляют дубликаты по хэшу текста или `chunk_id`,
объединяют ранговые оценки и только затем фильтруют и реранжируют. Квоты каналов
не дают одному поиску полностью вытеснить другой, а ограничение количества
чанков одного источника повышает разнообразие final top-K.

## Проверенные доказательства между сообщениями

После успешного проверяемого ответа диалог хранит компактный evidence ledger:
только `chunk_id`, источник, раздел, страницу и номер обмена — без текста чанка.
При итоговых формулировках («собери итог», «обобщи», «сопоставь») сервер повторно
читает эти чанки из SQLite и добавляет их кандидатами к текущему поиску. Поэтому
старый полный текст не путешествует по истории, но подтверждённые ранее факты
можно безопасно использовать для синтеза.

Ответ `unknown` при прошедшем relevance-gate получает одну дополнительную
проверку модели. Ошибка JSON, ссылок или цитат также допускает одну исправляющую
попытку; повторная ошибка всегда заканчивается безопасным отказом. Номер `[N]`
канонизируется по реальному `chunk_id`. Для PDF сервер может восстановить
дословную исходную цитату после однозначного совпадения, если различие состоит
только в пробелах или переносе слова вида `сло- во`; регистр, пунктуация и
смысловая похожесть не нормализуются.

## Жизненный цикл чанка

Полный текст чанка читается из `data/rag_index.sqlite3`, участвует в поиске и
передаётся модели только для текущего ответа. После запроса в JSON сообщения
записываются:

- `run_id` и `chunk_id`;
- `source`, `title`, `section`, page и стратегия;
- similarity, direct/context/fusion и reranker scores;
- параметры candidate top-K, final top-K и порога.

Сам текст чанка в обычный диалог не копируется. Это не мешает повторно открыть
исходный фрагмент из индекса и не раздувает будущий контекст. Изолированные
лаборатории сравнения Дней 22–24 сохраняют полную выдачу, потому что она нужна
для воспроизводимого анализа.

## Ответ вне локальной базы

После безопасного «не знаю» пользователь может явно дать одну из команд:

- `Ответь вне базы знаний`;
- `Используй свои знания`;
- `Используй доступные инструменты`.

Только текущее сообщение обходит документальный поиск. Если MCP разрешены и
запущены, агент может использовать подходящие инструменты; общий выключатель MCP
по-прежнему имеет приоритет. Сервер независимо от формулировки модели добавляет
метки:

```text
Ответ вне локальной базы знаний.
...
Источники локальной базы: не использовались.
```

Следующее сообщение снова проходит RAG. Никакой постоянный переключатель в
диалоге не сохраняется.

## Что проверено сейчас

Локальными fake/mock-проверками подтверждено:

- contextual rewrite не получает старые блоки источников и цитат;
- второй вопрос использует direct и contextual поиск с весами 70/30;
- обычный JSON-снимок не содержит полного текста чанка;
- явный выход из базы помечается и действует один ход;
- следующий вопрос автоматически возвращается к RAG;
- evidence ledger повторно загружает подтверждённый чанк из SQLite;
- неверный номер ссылки исправляется только по валидному `chunk_id`;
- PDF-перенос восстанавливается в точную исходную цитату только при однозначном
  совпадении.

Реальный прогон DeepSeek выполнен на двух сценариях по 10 сообщений. После
оптимизации получено 7 полезных документальных ответов из 19 против 5 из 19 в
исходном прогоне; ожидаемый PDF присутствовал в retrieval в 17 из 17 проверяемых
ходов против 12 из 17. Короткий контроль последних исправлений дал 4 проверенных
ответа из 5, все четыре — с программно валидными источниками и цитатами. Пятый,
итоговый, был безопасно отклонён из-за исправленного моделью PDF-переноса;
последующая узкая локальная проверка подтверждает восстановление именно такого
однозначного исходного фрагмента. Полные результаты находятся в
`docs/DAY25_RESULTS.md`, `docs/DAY25_RESULTS_AFTER_OPTIMIZATION.md` и
`docs/DAY25_CONTROL_AFTER_FIX.md`.

Отдельный реальный прогон автоматической маршрутизации сохранён в
`docs/DAY25_AUTO_ROUTING_RESULTS.md`: два взаимозависимых сценария, 25 сообщений,
цель Task State сохранена 25/25, источники маркированы 25/25, ожидаемый PDF
найден 18/18, маршруты первого прогона совпали с ожиданием 23/25. Все 13
выданных документальных ответов прошли строгую проверку цитат; шесть
документальных вопросов завершились безопасным `unknown`. Две обнаруженные
ошибки правил — инвестиционное слово «инструменты» и отрицание «не добавляя
актуальных данных» — после прогона исправлены и покрыты локальной проверкой.
